# 09 — Фильтры `organizer`/`registered` для /my-events (D03)

**Требования:** R116

**Blocked by:** 04
**Зона:** `backend/apps/events/filters.py`, `backend/apps/events/tests/`
**Волна:** 5 (добавлен постфактум, не конфликтует по зоне с 05/07)
**Status:** ready

## Почему этот таск появился

D03 (см. `manifest.md`): спецификация §8 описывает фильтры `organizer` и `registered` для
наполнения `/my-events`, но ни таск 03, ни таск 04 не получили это в свои критерии приёмки —
недосмотр при резке тасков в Phase 4, не ошибка исполнителей. Таск 07 уже построил фронтенд под
эти параметры («что организую» → `?organizer=<id>`, «куда записан» → `?registered=true`); без
этого таска обе вкладки `/my-events` показывают весь список вместо отфильтрованного.

## Разделы спецификации

§8 (Поиск, фильтры, список) — сниппет `EventFilter` с полями `organizer`/`registered`.

## Критерии приёмки

- [ ] `EventFilter` дополнен: `organizer = NumberFilter(field_name="organizer_id")` —
      `?organizer=<id>` возвращает только события этого организатора
- [ ] `registered = BooleanFilter(method="filter_registered")` — `?registered=true` возвращает
      только события, на которые записан ТЕКУЩИЙ аутентифицированный пользователь;
      `?registered=false` или отсутствие параметра — без изменений
- [ ] Для анонима `?registered=true` возвращает пустой список (не 401, не 500) — метод фильтра
      проверяет `request.user.is_authenticated` и при `False` отдаёт `queryset.none()`
- [ ] `FilterSet` получает доступ к `request` (уже проброшен DRF/django-filter автоматически
      через `self.request` в методе фильтра — отдельно ничего пробрасывать не нужно)
- [ ] Тесты в `apps/events/tests/test_filters.py` (дополни существующий файл, не создавай
      новый): `?organizer=<id>` возвращает только события этого организатора и не возвращает
      чужие · `?registered=true` аутентифицированному, у которого есть запись на событие X и нет
      на Y, возвращает только X · `?registered=true` анониму → пустой список, не ошибка ·
      `?organizer=<несуществующий id>` → пустой список, не ошибка
- [ ] Полный набор (`docker compose exec backend pytest`) остаётся зелёным — 52 существующих
      теста плюс новые
